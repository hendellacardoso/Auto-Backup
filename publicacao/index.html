Como funciona

Configure uma vez. O backup acontece sozinho.

Você cadastra o servidor, escolhe os bancos e o horário. O sistema gera o arquivo com a ferramenta oficial de cada banco, compacta, envia para os destinos e registra tudo no histórico.

Bancos suportados

Cada banco com a sua ferramenta oficial de backup

Os arquivos gerados são os mesmos que um DBA faria à mão — e podem ser restaurados fora do sistema, se precisar.

SQL Server

BACKUP DATABASE gera o .bak com COPY_ONLY e CHECKSUM, sem interferir na sua rotina de backups. Usuário SQL ou autenticação do Windows.

PostgreSQL

pg_dump no formato custom (.backup) e restauração com pg_restore, encerrando as conexões ativas do banco de destino.

MySQL e MariaDB

mysqldump com --single-transaction, rotinas, triggers e eventos. Restaura até com outro nome de banco.

Oracle

Data Pump (expdp/impdp) por schema, com REMAP_SCHEMA para restaurar em outro schema.

Como usar

Passo a passo

Escolha um assunto. Os botões “Ver tela” abrem a tela correspondente no visor.

Primeiro acesso

  1. Abra o API2Dev Backup. O Painel mostra os backups do dia, as falhas, as tarefas ativas e o espaço usado.
  2. O ícone fica na bandeja do sistema (ao lado do relógio). Pelo menu dele você abre o painel, executa um backup na hora, pausa os agendamentos ou abre a pasta de backups.
  3. Em Configurações → Geral, escolha a pasta local dos backups e marque Iniciar junto com o Windows.
  4. Fechar a janela não encerra o sistema: ele continua na bandeja. Para sair de vez, use Sair no menu da bandeja.

Cadastrar uma conexão

  1. Vá em Conexões → Nova conexão e escolha o tipo: SQL Server, PostgreSQL, MySQL/MariaDB ou Oracle.
  2. Informe servidor, porta (ou a instância no SQL Server), usuário e senha. No SQL Server também é possível usar a autenticação do Windows.
  3. Clique em Testar conexão. Depois, o botão Bancos lista os bancos encontrados no servidor.
  4. SQL Server em outro servidor: informe a pasta de backup no servidor e o caminho de acesso local à mesma pasta (ex.: \\SERVIDOR\Backup).
  5. Oracle: cada item listado é um schema. Informe o DIRECTORY do Data Pump (padrão DATA_PUMP_DIR).

Criar uma tarefa de backup

  1. Em Tarefas de backup → Nova tarefa, dê um nome e escolha a conexão.
  2. Marque os bancos de dados (há Marcar todos e Desmarcar).
  3. Agendamento: em Horários fixos, adicione um ou mais horários e escolha os dias da semana; em Intervalo, informe de quantos em quantos minutos.
  4. Compactação: marque Compactar em ZIP e, se quiser, defina uma senha (AES-256). Guarde essa senha.
  5. Máximo de backups por dia (por banco) e Manter backups por (dias). Use 0 para ilimitado.
  6. Escolha os destinos e quando receber e-mail. Salve e clique em Executar para testar na hora.

Google Drive, FTP e e-mail

  1. Google Drive: no Google Cloud Console, ative a Google Drive API e crie um ID do cliente OAuth do tipo App para computador. Cole o Client ID e o Client Secret em Configurações → Google Drive e clique em Conectar conta Google.
  2. FTP: em Configurações → FTP, informe servidor, porta, usuário, senha e pasta remota. Marque FTPS se o servidor usar TLS e clique em Testar conexão.
  3. E-mail: em Configurações → E-mail, informe o servidor SMTP, usuário, senha, remetente e destinatários (separados por vírgula). No Gmail, use uma senha de app. Clique em Enviar e-mail de teste.
  4. Na tarefa, marque Enviar para o Google Drive e/ou Enviar para o FTP. Se quiser, desmarque Manter cópia local.

Histórico e restauração

  1. Em Histórico / Restaurar, filtre por texto, tarefa, status e período. Os ícones mostram onde o arquivo está: local, Google Drive e/ou FTP.
  2. O botão de log mostra cada passo da execução; o de pasta abre o arquivo no Windows Explorer.
  3. Para restaurar, clique em Restaurar, escolha a conexão e o banco de destino. Use outro nome para criar uma cópia sem sobrescrever o original.
  4. Se o ZIP tiver senha, ela é usada automaticamente. Confirme e acompanhe o log em tempo real.
  5. Também é possível Restaurar de um arquivo qualquer: .zip, .bak, .backup, .sql ou .dmp.

Serviço do Windows

  1. Em Configurações → Serviço do Windows, clique em Instalar serviço e aceite a permissão de administrador.
  2. Com o serviço ativo, os backups rodam mesmo sem ninguém logado. O aplicativo da bandeja passa a só gerenciar as configurações.
  3. O serviço roda como LocalSystem. Para SQL Server com autenticação do Windows ou pastas de rede, altere a conta de logon do serviço “API2Dev Backup” em services.msc.
  4. A versão portátil não instala o serviço; para isso, use o instalador.

Dúvidas frequentes

Perguntas e respostas

O que é a “quantidade máxima de backups por dia”?

É quantas cópias de cada banco ficam guardadas por dia. Se a tarefa roda a cada hora e o limite é 3, ao fazer o 4º backup do dia o mais antigo daquele dia é removido (na pasta local, no Drive e no FTP).

O computador precisa ficar logado?

Não, se você instalar o serviço do Windows. Sem o serviço, os backups rodam pelo aplicativo da bandeja, que inicia junto com o Windows.

Consigo abrir o ZIP fora do sistema?

Sim. O ZIP usa AES-256 e abre no 7-Zip, WinRAR e similares com a senha definida na tarefa.

O backup do SQL Server atrapalha meus backups atuais?

Não. Os backups são feitos com COPY_ONLY, que não altera a cadeia de backups diferenciais e de log.

Meus dados passam por algum servidor da API2Dev?

Não. O sistema roda no seu computador ou servidor e envia os arquivos direto para a pasta, o Google Drive ou o FTP que você configurou.

Posso restaurar sem sobrescrever o banco original?

Sim. Na restauração, informe outro nome de banco (ou de schema, no Oracle). Também dá para restaurar em outra conexão do mesmo tipo.

E se um backup falhar?

O histórico registra o erro com o log completo, o Painel mostra a falha e, se configurado, você recebe um e-mail com o relatório.
